# dsh-mobile-link

用一行配对串或三行字，把手机接到 DeepSeek Harness 桌面端：手机可以看电脑上的会话、接着往下聊。

**网络范围先说清楚**（这一节写的就是能做到什么、做不到什么）：

| 场景 | 走法 | 用户要做的事 |
|---|---|---|
| 手机与电脑同一局域网 | 内置中继（插件自己在电脑上起一个） | 填面板三行字 |
| 不在同一网络（手机流量 / 电脑在别处） | **隧道**：插件自己下载并拉起 cloudflared，映射出一个随机公网 HTTPS 地址 | 开一个开关，复制一行配对串 |
| 不想经过任何第三方 | **直连**：全局 IPv6 或公网 IPv4，HTTPS + 自签证书 + 指纹固定 | 开一个开关，核对一次指纹 |
| 你本来就有公网服务器 | 自部署 `relay/server.mjs`（零依赖单文件，支持 Docker / Caddy HTTPS） | 部署一次，填公网地址 |

- 三种走法都是**两端只做出站或只开一个受保护的入口**，不需要公网 IP 的那两条路径是默认路径；跨网时不需要用户跑任何命令。
- 桌面面板显示中继地址、房间号、中继口令（或一行配对串），手机端「设置 → 连接电脑」填进去 / 粘上去即绑定——没有二维码，也没有会过期的配对码。
- 手机读的是电脑上真实的会话（同一个 session，不是镜像副本），发出去的消息进入桌面端 agent 的收件箱。
- **跨网时中间那一跳只看得到密文**：请求与应答都套一层房间口令派生的 AES-256-GCM 信封（见「端到端信封」）。

## 组成

```
                                        ┌── relay/server.mjs（你部署的，或公共的）
桌面端插件（index.js + client.js）──────┼── tunnel.mjs（拉起 cloudflared → 随机公网地址）
                                        └── direct.mjs（公网 HTTPS + 自签证书/指纹）
                                                  ↑ 三条路都进同一个 rpc.mjs / handle()
手机端 App（LinkTransport：relay/tunnel/direct + LinkCrypto 信封）
```

三条路共用同一个请求处理函数，权限口径不会两边分叉；三段都可替换：中继可以自托管在任意 VPS、Docker、群晖、树莓派上。

## 一、中继（同一局域网时不用部署）

中继是唯一需要「两端都能访问」的东西，它不存任何数据。有两条路：

**默认：桌面端自己起一个。**「中继地址」留空即可——插件会在桌面端进程内启动中继，监听本机 8787（被占用时自动换空闲端口），并把**当前网卡地址**显示在面板上。地址在每次启动时重新探测，换了 Wi-Fi、DHCP 续了新 IP 都不会留下一个打不开的地址。手机与电脑在同一局域网时，照面板填一次即连，零部署。

**跨网络：自己部署一个。** 手机走流量、或两端不在同一网段时，才需要下面这种方式，填到面板的「中继地址」里（或 `DSH_MOBILE_LINK_RELAY`）。

### 方式 A：Docker

```bash
docker build -t dsh-mobile-link-relay .
docker run -d --restart unless-stopped -p 8787:8787 --name dsh-link-relay dsh-mobile-link-relay
```

### 方式 B：直接跑（Node 20+，零依赖）

```bash
node relay/server.mjs --port 8787 --host 0.0.0.0
```

### 方式 C：HTTPS（推荐，手机端从公网连时必须）

Caddy 一行搞定自动证书：

```
link.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

> Android 9 起默认禁止明文 HTTP。若手机 App 的 `usesCleartextTraffic` 未开启，公网必须用 `https://`；局域网内 `http://` 可用。

自检：`curl https://link.example.com/health` 返回 `{"ok":true,...}` 即可。

> 已填的地址连不上、且是内网/本机地址时，启动会自动改用本机中继，并在面板上说明换过地址；填的是公网地址则只报错不改写，因为那属于运营方的问题。

## 二、安装桌面端插件

插件是一个标准 DSH 插件包（`package.json` 的 `dsh.bundle.patch` + `dsh.client`），放进任意 profile 都能用。

### 方式 A：官方命令直装（推荐）

`dsh` CLI 的 `plugin` 子命令把安装转发给 profile 内的 pnpm，支持从 GitHub 直装：

```bash
# 从 GitHub 仓库的 desktop-plugin 子目录安装（本插件的发布位置）
dsh plugin --profile <profile名> add "github:xiaobaga281/dsh-mobile#path:desktop-plugin"

# 或从本地目录安装（先 git clone 或下载本目录）
dsh plugin --profile <profile名> add "link:/路径/dsh-mobile-link"
```

安装后重启桌面端，侧边栏会出现「手机联动」。

### 方式 C：发布包（tgz）

发布产物不留在源码目录里 —— 打完就删，历史包都在 App 的 GitHub release 下（`rc.194` 起随版本一起挂）。
这台机器上 `npm pack` 会卡在 node_cache 权限，所以直接按 npm 的布局用 tar 复现（根目录必须是 `package/`）：

```bash
node --check index.js && node .test/e2e-relay.mjs        # 先绿
tar -czf dsh-mobile-link-<版本>.tgz --transform 's,^,package/,' \
  client.js index.js package.json README.md direct.mjs e2e.mjs rpc.mjs relay/server.mjs tunnel.mjs icon.svg cordis.patch.yml
sha256sum dsh-mobile-link-<版本>.tgz                      # 发布时要和 GitHub 服务端回读的对得上
```

装法：解压后把 `package/` 里的内容覆盖 `%USERPROFILE%\.dsh\plugins\dsh-mobile-link`，**重启桌面端生效**。

### 方式 B：放进插件目录（Desktop 桌面客户端）

把本目录复制/链接到 `%USERPROFILE%\.dsh\plugins\dsh-mobile-link`，然后在 profile 的 `package.json`（`~/.dsh/profiles/desktop/package.json`）：

```jsonc
{
  "dependencies": {
    "dsh-mobile-link": "link:C:/Users/you/.dsh/plugins/dsh-mobile-link"
  },
  "dsh": {
    "profile": {
      "bundles": [
        // …已有条目…
        "dsh-mobile-link"
      ]
    }
  }
}
```

再让包管理器建好链接（profile 目录下执行）：

```bash
pnpm install
```

重启桌面端。侧边栏会出现「手机联动」。

### 或者手动建链接（不想跑 pnpm 时）

```bash
# profile 目录：~/.dsh/profiles/desktop
ln -s /path/to/dsh-mobile-link node_modules/dsh-mobile-link
```

并在 `bundles` 里加上 `"dsh-mobile-link"`。

### 配置中继地址

三种方式，任选：

- 留空（默认）：桌面端自己起中继，同一局域网照着面板填即可。
- 面板里填：侧边栏「手机联动」→ 底部「中继地址」→ 保存。跨网络时填公网地址。
- 环境变量：启动桌面端前 `export DSH_MOBILE_LINK_RELAY=https://link.example.com`。

## 三、配对（同一局域网：手填三行字）

1. 桌面端侧边栏 →「手机联动」→ 点「启动联动」（默认关闭，状态重启后保留），面板随即显示三行内容：**中继地址 / 房间号 / 中继口令**，每行带「复制」。
2. 手机端 →「设置 → 连接电脑」→ 把这三项填进「中继地址 / 房间号 / 口令」→ 连接。
3. 连上后面板里会出现这台手机，可随时「移除」；移除后它下次调用直接 401。

这三项都是持久的：重启桌面端、重启 App 都不用重新配对。口令（128 位房间密钥）就是这把锁的钥匙——谁拿到它，谁就能连上这台电脑，所以别截图发群。想让它失效就点面板上的「重置配对」，房间号和口令一起换新。

内置中继只监听本机，所以开箱范围是**同一局域网**。手机走流量、或电脑在另一个网络时，看下一节。

## 三·五、跨网（隧道默认 / 直连高级）

面板「跨网连接」里两个开关，各自独立，可以只开一个：

| 走法 | 需要什么 | 中间那一跳 | 用户要做什么 |
|---|---|---|---|
| **隧道**（默认） | 无 —— 插件自己从 Cloudflare 官方地址下载 `cloudflared` 并拉起 | Cloudflare 边缘（只见密文） | 点一下开关，复制配对串 |
| **直连**（高级） | 这台机器有全局 IPv6，或公网 IPv4 / 已做端口映射 | 无，手机直接打到电脑 | 点一下开关，核对证书指纹 |

- **不需要跑任何命令**：下载、`--version` 自检、拉起、出地址都在插件里做；下载不下来就明说「不可用」并给手动安装指引，不假装「正在连接」。
- **下载物只落在插件自己目录**（`<插件>/bin`、`<插件>/data`，自签证书也在那里）：**卸载插件连带消失**，不在 `~/.dsh` 留残留；面板另有「清除已下载组件」兜底。
- **配对串**是一行 `dshlink1:…`（地址 + 口令 + 机器名 + 直连指纹）。手机「设置 → 连接电脑 → 粘贴配对串」一次搞定，不用抄随机长地址，也不用抄 128 位口令。
- **隧道地址每次重启都会变**（quick tunnel 的性质），面板会写清楚；地址变了就重新复制一次配对串。
- **直连的证书是自签的**：信任锚是 SHA-256 指纹。配对串带指纹时首连即固定；不带时手机先取证、用户在界面核对后才落盘，之后任何别的证书都不接受。

```bash
node .test/cross.mjs        # 信封逐字节 / 配对串 / 直连 HTTPS / 清理，26 条
```

## 端到端信封

跨网时 TLS 在隧道边缘终结，所以请求与应答再叠一层用房间口令派生的 AES-256-GCM 信封：

```
key  = HKDF-SHA256(ikm=utf8(房间口令), salt="dsh-mobile-link-v1", info="rpc-aes-256-gcm", len=32)
信封 = { v:1, iv:base64(12B), ct:base64, tag:base64(16B) }
```

- 口令本身不再以明文出现在任何中间层可见的位置（隧道的 `x-link-key` 那一步也被搬进信封内的 header）。
- 口令错误、包体损坏、明文探测在服务端**不可区分**：都是同一个 401，不给探测者「猜对了没有」的信号。
- 手机端 `kernel/link/LinkCrypto.kt` 与本模块逐字节一致，跨语言测试向量在两端各钉一份（`LinkCryptoTest` / `.test/cross.mjs`）。

## 传输稳定性

链路是「手机 → 中继 → 电脑 → 中继 → 手机」，四段各自的弱网对策：

| 环节 | 机制 |
|---|---|
| 手机 → 中继 | 同一次逻辑调用带 `x-request-id`；网络层错误最多重试 3 次（600ms / 1.8s 退避），504（电脑 30 秒没应答）也再给一两次机会 |
| 电脑端去重 | 按 `x-request-id` 缓存最近 512 条应答（10 分钟 TTL）：「第一发其实到了、只是应答没回来」的重试拿到回放，**同一条消息永远不会执行两遍** |
| 电脑 → 中继（应答投递） | 结果 POST 失败自动补投最多 3 次（1s / 2.5s）—— 工作已经做完，不能让手机白等一个 504 |
| 电脑 → 中继（取活） | 拉取循环断线退避封顶 12 秒 + 抖动（以前 30 秒会贴着离线判定阈值，抖出「电脑不在线」假警报）；90 秒零进展的看门狗整体重启循环 |
| 中继 → 手机 | 电脑离线判定收紧为 45 秒（桌面最坏 38 秒必然刷新一次心跳），更早给出可定位的错误 |
| 兜底 | 单帧处理 20 秒超时防止一帧拖死轮询；中继重启后两端自动重注册；深睡/睡眠唤醒后看门兜底 |

幂等键是这套设计的核心：它把「重试」从危险操作变成默认动作 —— 发消息、切模型、拉历史
都敢重试，而不会出现重复回复。

## 安全模型

| 环节 | 保护 |
|---|---|
| 中继 | 必须出示房间密钥（`x-link-key`），房间号单独泄露无用 |
| 配对 | 手填的房间密钥即凭据，错误密钥返回 `401`；面板可随时重置房间与密钥 |
| 手机调用 | 每次都要配对时下发的设备令牌（`x-device-token`），移除设备即失效 |
| 桌面面板 | 复用 harness 自己的 loopback 围栏，局域网内他人拿不到房间密钥 |
| 跨网 RPC 入口 | 只监听 `127.0.0.1`（隧道指向它）；直连那一份公网 HTTPS 每个请求都要能解开信封 |
| 跨网载荷 | 端到端 AES-256-GCM 信封：隧道/中间层看不到口令、令牌与正文 |
| 直连证书 | 自签 + SHA-256 指纹固定（TOFU 核对一次），指纹不匹配就当没连上 |
| 权限范围 | 只能：列会话、读历史、发消息、取消当前轮次；不能执行工具、不能读写文件 |

已知边界（有意为之，写清楚比藏起来好）：

- 隧道由 Cloudflare 提供：它看不到内容，但能看到「有这么一条连接」与长度分布；介意的话用直连（不经过任何第三方）。
- 直连把一个端口开到公网，只接受口令正确且能解密的请求；不需要端口映射的前提是这台机器有全局 IPv6。
- 中继转发的是明文 HTTP 请求体。自托管时没有第三方；用公共中继请确认你信任运营者，或在中继前加 TLS 终止即可保护传输段。
- 桌面端开关机状态会体现在「手机在线 / 离线」上。
- 目前手机端只渲染文本与工具调用摘要，图片/附件、队列编辑、多轮 steer 不在范围内。

## 开发

仓库不含开发测试目录（`.test/` 内含作者本机路径，未随插件分发）。插件本体只用 Node 内置模块，无任何运行时依赖：

```bash
npm run check                       # 七个 JS 文件语法自检
npm run relay                       # 起中继
node .test/cross.mjs                # 跨网：信封 / 配对串 / 直连 HTTPS / 清理
```

## 版本

- v1.3.3：中继单包上限 512KB → 6MB（带图 prompt 的信封装不下了，电脑会话发图片在局域网这条路上永远是 413）；新增「单房间排队字节 ≤24MB」的兜底，条数上限不再是唯一护栏；
- v1.3.2：墓碑改记「删除时刻」——以前在面板里移除过某台手机，它那台设备就永远配不回来了：重新 `/pair/key` 签出令牌，`saveState()` 的读-合并-写却把磁盘上那份旧 id 墓碑并回来，刚签的设备当场被剔掉，手机表现为「刚连上就掉线」。现在比时间：`removedAt >= pairedAt` 才算删过，删除与重新配对谁晚听谁的；
- v1.3.1：插件面板自己滚（`.ml-root` 补 `flex:1 + min-height:0 + overflow-y:auto`）—— 以前中栏 `overflow:hidden` 裁掉超出部分，面板内容一长就滚不动；
- v1.3.0：跨网开关跨重启保持（卸载/热重载只收进程，不再把「开着隧道」写成关）；cloudflared 下载支持镜像回退；历史应答补发 `context` / `breakdown`，并加投影缓存兜底；
- v1.2.0：跨网三种走法 —— 隧道（自动下载 cloudflared）、直连（自签 + 指纹）、端到端 AES-256-GCM 信封；配对串 `dshlink1:` 一行粘贴；
- v1.1.0：传输稳定性 —— 请求幂等键（x-request-id）+ 弱网三段重试 + 应答补投 + 退避收紧，详见「传输稳定性」；
- v1.0.0：标准 DSH 插件格式（`dsh.bundle.patch` + `dsh.client`），displayName「手机互联」；
- 配对方式为面板三行手填（中继地址 / 房间号 / 口令），无二维码、无过期配对码；
- 面板支持按设备「移除」与「重置配对」，带忙碌态与错误提示；
- 中继为 `relay/server.mjs` 零依赖单文件，支持进程内自起（同局域网默认）、Docker、Caddy HTTPS 自部署。
